# Introduction

Week 8 introduces `git` and GitHub for version control.

:::{tip} Learning Objectives
After this session, you should be able to
 - Understand the purpose of version control.
 - Use and understand basic `git` functionality such as `add`, `commit`, `push`, and `pull` to work with `git` and GitHub repositories.
 - Use tools such as forking, branching, pull requests to work collaboratively on a GitHub repository.
 - Undestand the necessary items for sharing reproducible and sharable code, such as licenses and `README.md` files.
:::

#### draft planning notes


Highlight good practice:
 - Use meaningful variable names and clear code structure.
 - Keep raw data separate from processed outputs.
 - Record data sources, units, CRS and relevant processing decisions.
 - Use functions when a calculation needs to be repeated.
 - Check assumptions and validate results.
 - Keep analysis steps executable in a logical order.

Avoid reliance on undocumented manual changes to intermediate files.

 - Intro: what does it mean for work to be 'rigourous' and 'reproducible'? how can git and github assist with this?
 - What is git: repositories, commits, history
 - How to install git
 - Basics: init, add, commit, push, pull
 - Collaboration: forking, branching, pull requests (practical example)
